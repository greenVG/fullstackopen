sequenceDiagram
    participant browser
    participant server

    %% User types a note and clicks the "Save" button
    Note over browser: User writes a note into the input field on the page

    %% The browser sends a POST request to submit the new note to the server
    browser->>server: POST https://studies.cs.helsinki.fi/exampleapp/notes
    activate server

    %% The server processes the note and responds
    Note right of server: Server parses the request body,<br>adds the note to memory, and prepares a response

    %% The server responds with a redirect to reload the /notes page
    server-->>browser: 302 Redirect to /notes
    deactivate server

    %% Browser now follows the redirect, starting with an HTML fetch
    Note over browser: The browser follows the redirect and reloads the page

    %% HTML document is fetched again
    browser->>server: GET https://studies.cs.helsinki.fi/exampleapp/notes
    activate server
    server-->>browser: HTML document
    deactivate server

    %% CSS is fetched
    browser->>server: GET https://studies.cs.helsinki.fi/exampleapp/main.css
    activate server
    server-->>browser: the CSS file
    deactivate server

    %% JavaScript is fetched
    browser->>server: GET https://studies.cs.helsinki.fi/exampleapp/main.js
    activate server
    server-->>browser: the JavaScript file
    deactivate server

    %% The JavaScript on the page then fetches the updated data
    Note right of browser: The JavaScript runs and fetches the latest notes in JSON format

    browser->>server: GET https://studies.cs.helsinki.fi/exampleapp/data.json
    activate server

    %% The server responds with the updated list of notes (including the new one)
    server-->>browser: JSON data with all notes including the new one
    deactivate server

    %% Finally, the browser renders the new note
    Note right of browser: The browser executes JavaScript to update the DOM and display the new note
